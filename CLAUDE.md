# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

GadgetsUAE (gadgetsdxb.com) is a static Amazon affiliate tech deals site targeting UAE consumers. It is hosted on GitHub Pages with a custom domain. The site is built with vanilla HTML/CSS/JS — no framework or build step.

## Commands

```bash
# Sync product prices from Amazon PA-API (requires .env with API keys)
npm run sync

# Sync creator/influencer products
npm run sync-creators

# Search Amazon catalog
npm run search

# Discover trending products
npm run discovery

# Generate sitemap
node scripts/generate-sitemap.js

# Update prices locally
node update-prices.js

# Tests (Node built-in test runner, no dependencies)
npm test

# Regenerate category pages + buying guides from scripts/site-content.js
npm run build:pages

# Export the public JSON feed (assets/data/catalog.json, consumed by the Nibango app)
npm run build:data

# Everything: pages + feed + sitemap
npm run build
```

The site is served as static files; there is no bundler or lint step.

## Architecture

### Data Flow (v7, September 2026)
- **Curated catalog**: `assets/data/catalog-items.js` — ~125 products WITHOUT prices or photos (brand, model, specs, blurb, tier, tags, heat, amazon.ae search `query`, optional `asin`).
- **Legacy products with photos**: `assets/js/products.js` — 21 products with local images. Their old price fields are ignored.
- **Merge layer**: `assets/js/catalog.js` builds `window.CATALOG` from both, assigns categories (config in `Catalog.CATEGORIES`), builds affiliate URLs (`/dp/ASIN` when known, otherwise an amazon.ae search link with the tag) and powers search. UMD: also used by Node scripts and tests.
- **Rotation**: `assets/js/rotation.js` — deterministic, date-seeded (UAE midnight) selection: pick of the day, weekly trending, daily category spotlights, daily ordering. Same result for every visitor on a given day, no backend.
- **No prices are shown anywhere** — Amazon only allows prices that come live from its API, and the site has no API access yet (Creators API requires qualifying sales). Cards link out with "View on Amazon.ae".
- **Product photos**: drop files into `assets/images/<id>/` (any name) and run `npm run build` — `scripts/build-images.js` discovers them. `node scripts/fetch-image.js <id> <manufacturer-page-url>` downloads a brand's official og:image (never Amazon) and logs the source in `SOURCE.txt`. Discovered photos render with `object-fit: contain` on white; legacy lifestyle photos use `cover`.

- **Weekly refresh**: a scheduled cloud agent (Claude Code routine "GadgetsUAE weekly catalog refresh", Mondays 05:00 UTC) follows `docs/weekly-refresh.md` to add 4–6 trending products with official photos and pushes to main. Keep that playbook in sync with any schema change.
- **Public feed**: `assets/data/catalog.json` (built by `scripts/build-data.js`) — consumed by the Nibango app. Rebuilt nightly by `.github/workflows/daily-build.yml`.
- **Amazon sync scripts** (`scripts/amazon-*.js`) are kept for when Creators API credentials arrive; `.github/workflows/amazon-sync.yml` is manual-only until then.

### Frontend
- Each HTML page includes shared components via fetch: `menu.html` (nav) and `footer.html`.
- `assets/js/script.js` — Loads menu, handles mobile nav, highlights active link.
- `assets/js/product-renderer.js` — `ProductRenderer`: photo cards, typographic "visual" cards for products without photos, the pick-of-the-day hero and compact rows.
- `assets/js/page.js` — page controllers keyed by `<body data-page="home|category|products|deals|guide|favorites">`.
- **Generated pages**: category pages (`gaming.html`, `mobiles.html`, …, `wearables.html`, `accessories.html`) and `guides/*.html` + `guides.html` are generated by `scripts/build-pages.js` from `scripts/site-content.js` (editorial copy + FAQs). Edit the content file, not the HTML.
- `assets/js/analytics.js` — Custom localStorage-based analytics (page views, searches, product clicks, favorites).
- `analytics-dashboard.html` — Password-protected analytics dashboard.
- `posts/` — Hand-written blog posts (one HTML file per product); not generated.

### Configuration
- `.env` — Amazon PA-API credentials (`AMAZON_ACCESS_KEY`, `AMAZON_SECRET_KEY`, `AMAZON_ASSOCIATE_TAG`). Not committed.
- `assets/js/config.js` — Firebase and analytics config. Not committed. Copy from `config.example.js`.
- Marketplace is `www.amazon.ae` (UAE).

### SEO
- `sitemap.xml` and `robots.txt` at root.
- `scripts/generate-sitemap.js` regenerates the sitemap.
- Pages include JSON-LD structured data via `assets/js/jsonld-injector.js`.
- CSP headers are set via meta tags in HTML.

## Key Conventions

- Product IDs are slugs (e.g., `kindlecolor`, `bambu-lab-a1`) matching directory names under `assets/images/`.
- Affiliate links: legacy `amzn.to` shortlinks or `amazon.ae/dp/ASIN?tag=gadgetsdxb-21`; curated items without a verified ASIN use `amazon.ae/s?k=<query>&tag=gadgetsdxb-21`. Always `rel="sponsored noopener noreferrer"`.
- The site content is in English; code comments and documentation are often in Spanish.
- Never render prices on the site until a live Amazon API feed exists.
- Unit tests live in `tests/*.test.js` (`node --test`); add tests for any new logic in `catalog.js`, `rotation.js` or `scripts/`.
